퍼소나 분석 스킬 v2

아이디어·통계·리서치 자료로 근거 있는 퍼소나를 문답하며 만들고, 사업 목적에 맞는 메인 퍼소나를 고른 뒤, 인사이트를 기획·KPI 결정까지 연결하는 작업 흐름입니다.

기반: GitHub 퍼소나 스킬 7종 v1: 라라스윗 실습 (제품형) v2: AI 실전 창업 부트캠프 문답 실습 (프로그램형)

WHAT'S NEWv1에서 v2로 바뀐 것

점진 문답 루프

질문은 2~4개씩, 추천안과 이유를 함께. 빈 질문지 대신 초안부터 보여주고 반응을 받는다.

사업 유형 분기

제품형은 이익 관점(v1), 교육·공공 프로그램형은 사업 목적 관점(발주처 KPI·대체 불가성 등)으로 메인을 고른다.

설정 → 지역 맥락

주최·규모·지역을 먼저 확정. 지역 통계가 퍼소나 서사를 바꾼다.

층별 신뢰도 · [대리] 라벨

통계 근거와 개인 행동의 신뢰도를 따로 단다. 다른 지역 자료는 [대리]로 표시.

보완관계 분석

비교표에 '강점' 행을 넣어 퍼소나끼리 빈 곳을 채우는 조합(혼합팀)을 찾는다.

인사이트 → KPI

인사이트가 '성공의 정의'를 바꾸면 성과지표를 다시 설계한다. 여정지도는 요청 시에만.

FLOW전체 흐름

초록 점은 v1에서 이어온 단계, 앰버 점은 v2에서 새로 생기거나 크게 바뀐 단계입니다. 각 단계 끝의 확인 지점에서 사용자가 확정해야 다음으로 넘어갑니다.

할 것

층별 신뢰도 v2

한 퍼소나 안에서도 근거의 단단함이 다릅니다. 중간(통계) / 낮음(개인 행동)처럼 나눠 표기하면, 규모·경향은 믿되 일과·우회 방법은 인터뷰로 검증해야 한다는 게 한눈에 보입니다. 자료 5개 미만이면 프로토 퍼소나로 명시합니다.

CASE실전 적용: AI 실전 창업 부트캠프 (가상)

2026-11-10 문답에서 퍼소나를 찾아간 순서입니다. 각 장면에서 스킬에 들어간 규칙을 앰버색으로 표시했습니다.

설정
주최 유디임팩트 × 창업진흥원, 10주 · 30명 · 오프라인. 퍼소나는 메인 1 + 서브 2.
→ 1-1 프로그램형 기본 설정을 퍼소나보다 먼저
초안 반응
초안 A·B·C 중 B를 '전환기 직장인'에서 '대학생 창업자'로 교체.
→ 초안 먼저 · 교체는 이유 묻지 않고 반영 + 변경 이력
근거 보강
쉬었음 청년 통계, 대학생 창업 기피 요인(실패 위험 40.8%), 소상공인 디지털 역량(기초·입문 83.3%)으로 프로토 퍼소나 뼈대.
→ 통계 기반 프로토 순서 · 층별 신뢰도
메인 확정
A(취준·재도전 청년). 이유: 정책 명분 · 운영사 '실행' 철학 일치 · B는 대학 창업지원단 등 대체재가 많음.
→ 4-B 사업 목적 관점 · 이유 3개
지역
대전 확정. 대전은 비수도권 중 드문 청년 순유입 지역 → 메인을 '서울 취준 끝에 돌아온 청년'으로. 교육장은 창업진흥원이 운영하는 대전 팁스타운.
→ 1-2 지역 맥락 레이어 · [대리] 근거
카드
메인 '한재윤(28)' 심층 카드, 서브 '이서진(23)'·'박민호(31)' 간이 카드, 비교표와 정원 배분 15·8·7명.
→ 메인 심층 / 서브 간이 · 정원 배분
인사이트
재윤이에게 창업은 목적이 아니라 재기의 수단 → 성과지표를 다시 설계.
→ '목적 vs 수단' 유형 · 인사이트 → KPI
대기
고객여정지도는 사용자가 요청할 때까지 진행하지 않음.
→ 여정지도 게이트

VERIFY검증 설계: 4채널 × 호·불호

채널호 신호불호 신호주의
리뷰·후기재구매·재참여·추천"기대보다", 이탈 이유협찬 여부
CS·문의 보이스재입고·다음 기수 문의환불·불만·같은 질문 반복문제 쪽 편향
인터뷰묻기 전에 대체 경험을 말함포기·다른 대안으로 이동과거 행동만
만족도 조사4~5점 + 재참여 의향낮은 점수 + 이유의향 ≠ 행동

2채널 이상 같은 방향이면 판정 · 1채널이면 보류 · 엇갈리면 퍼소나 재분할. 불호는 적합성 · 기대 불일치 · 운영 조건 · 편의 · 타이밍으로 원인을 나눕니다.
