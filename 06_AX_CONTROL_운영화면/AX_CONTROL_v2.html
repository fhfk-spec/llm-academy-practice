Operating system / team rules

일은 맡기고,
기준과 근거는 지킨다.

공통 규칙 CLAUDE.md 요약. 2026-11-12에 ChatGPT 제작물에서 좋은 원칙을 골라 합쳤습니다.

01 · 허브 앤 스포크

총괄 PM만 호출·취합·조정·보고. 에이전트끼리 부르지 않음.

02 · 파일이 기억

지시문 6요소, handoffs/ 인수인계서, decisions.md를 먼저 읽음.

03 · 남이 검토

정해진 검토자를 새로 호출. qa-reviewer는 읽기 전용 최종 관문.

04 · 근거 ID와 태그

R·N·D 근거, [확인]·[추론]·[가설]·[미확인]. "사용자 설명"과 "공식 문서" 구분. 합침

05 · 경보 ≠ 처분

위험 표시는 지원 신호. 처분 안내는 기관 확정 뒤. 합침

06 · 데이터 정직성

데이터 없음 ≠ 0. 목표선 ≠ 실적. 원본은 읽기 전용, 정정은 이력과 함께. 합침

07 · 발송 안전

초안 기본. 위임·도구가 있어도 사용자 확인 후, 개인별·숨은참조, 발송 기록, 중복 방지 키. 합침

08 · 개인정보

기관 → CJ는 집계만(C안), 0 / <5 / n. 실명은 raw/에만, git 제외.

09 · 공정성

소수 사례 일반화 금지. 경제력·개인 사정을 선발 기준으로 쓰지 않음. 진술과 관찰 분리. 합침

1주차에서 배운 것

사례 A · 다른 우선순위

인턴 지원을 먼저 해 보고 취업 연계로 가려 함

사례 B · 참여 의사

취업 관심 없고 쉬고 싶음

사례 C · 수준 불일치

중상위 개발자, 과정 단계와 맞지 않음

잔류자 공통점: 창작의 재미, 하고 싶은 마음, 적극성. 3건이라 일반화하지 않고, 4·6·9주차 체크인(새 우선순위·흥미·난이도)으로 확인합니다.
